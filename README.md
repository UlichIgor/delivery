# Feast Sushi

Feast Sushi — вебзастосунок ресторану, у якому можна переглянути каталог страв, відфільтрувати його за категоріями та зібрати кошик. Цей файл пояснює, як користуватися наявними можливостями сайту, які розділи доступні та які функції ще перебувають у планах розробки.

## Як користуватися сайтом

### Перегляд меню

На головній сторінці розміщені рекламний банер і каталог страв. Каталог можна відфільтрувати за категорією або знайти страву за назвою чи описом. Кнопка в банері прокручує сторінку до меню.

### Додавання страв до кошика

Натисніть «До кошика», щоб додати страву. Лічильник у шапці показує загальну кількість одиниць, а повторне додавання збільшує кількість уже вибраної позиції. Кошик зберігається в браузері після перезавантаження сторінки.

Натисніть значок кошика, щоб переглянути замовлення. Кнопки «+» і «−» змінюють кількість, а кнопку видалення можна використовувати з клавіатури. Ціни та підсумок форматуються у гривнях. Кнопка оформлення передає замовлення до Supabase, якщо база налаштована.

## Розділи сайту

У верхній навігації доступні такі розділи:

- **Головна** — рекламний банер, пошук, фільтри та каталог страв.
- **Про нас** — інформація про ресторан і порядок замовлення.
- **Зона доставки** — інформація про доставку в Чернігові та перехід до менеджера для уточнення умов.
- **Залишити відгук** — форма з оцінкою; відгук зберігається в Supabase або готується для надсилання через WhatsApp.
- **Контакти** — телефон, WhatsApp і форма повідомлення менеджеру.

Каталог і фільтр категорій відображаються незалежно від вибраного розділу. Навігація між сторінками відбувається без повного перезавантаження сайту.

## Що варто знати про поточну версію

- Якщо налаштовано Supabase, меню завантажується з таблиці `products`; інакше використовуються резервні позиції з коду.
- Оформлення замовлення доступне лише з налаштованим Supabase. Онлайн-оплати немає: менеджер має зв’язатися з клієнтом для підтвердження.
- Вартість, години та точні межі доставки потрібно уточнювати у менеджера.

Отже, каталог, кошик і передавання замовлення реалізовані; оплата та відстеження статусу замовлення на сайті не передбачені.

## Плани подальшої розробки

Можливі наступні кроки розвитку Feast Sushi:

1. Додати онлайн-оплату й перегляд статусу замовлення.
2. Створити обліковий запис клієнта та історію покупок.
3. Додати адміністративний інтерфейс для керування меню й замовленнями.
4. Публікувати лише підтверджені умови доставки та актуальні посилання на сторінки ресторану в соцмережах.
5. Розширити автоматизовані перевірки сценаріїв кошика й оформлення.

Це можливі напрями розвитку, а не функції, доступні в поточній версії.

## Технології та структура

Застосунок побудований як односторінковий сайт (SPA) на React. Основна логіка меню, фільтра категорій і кошика розташована в `src/App.jsx`. Маршрути між розділами налаштовані через React Router із `HashRouter`. Спільні частини інтерфейсу — шапка, картки меню, категорії, кошик і нижня частина сайту — винесені в `src/components/`, а сторінки розділів — у `src/pages/`.

Інтерфейс стилізовано за допомогою SCSS. Webpack і Babel використовуються для підготовки застосунку до розробки та публікації. Статичні ресурси розташовані в `public/` і `src/images/`, а production-збірка створюється в каталозі `build/`.

Основні технології:

- React і JavaScript (JSX) — інтерфейс і логіка застосунку.
- React Router — навігація між сторінками.
- SCSS — стилі.
- React Bootstrap і React Icons — компоненти інтерфейсу та іконки.
- Webpack і Babel — обробка та збірка файлів.

## Запуск проєкту

Для локального запуску потрібні встановлені Node.js та npm. У терміналі перейдіть до каталогу проєкту й виконайте:

```bash
npm install
npm start
```

Перша команда встановить залежності, друга запустить режим розробки. Після запуску відкрийте [http://localhost:3000](http://localhost:3000) у браузері.

## Збірка та публікація

Щоб перевірити production-збірку, виконайте:

```bash
npm run build
```

Готові файли буде створено в каталозі `build/`. Для публікації на GitHub Pages у проєкті налаштована команда:

```bash
npm run deploy
```

Вона спочатку створює production-збірку, а потім публікує каталог `build/` у гілці `gh-pages`. Для публікації потрібні відповідні права доступу до репозиторію та налаштування GitHub Pages.


## Підключення Supabase

У проєкті підготовлена інтеграція із Supabase для каталогу, відгуків, клієнтів і замовлень.

### Що створює міграція

Файл `supabase/migrations/202611160001_initial_schema.sql` створює таблиці:

- `products` — 23 стартові позиції меню; каталог завантажується з бази, коли налаштовані ключі.
- `customers` — ім’я та телефон клієнта.
- `orders` і `order_items` — адреса, коментар, статус, склад і сума замовлення.
- `reviews` — оцінка та текст відгуку; нові відгуки очікують модерації.

Для замовлень використовується функція `submit_order`: суми та ціни беруться з бази даних, а не з браузера. Політики RLS не дозволяють відвідувачам читати дані клієнтів або чужі замовлення.

### Налаштування проєкту

1. Створіть проєкт у [Supabase](https://supabase.com/).
2. Відкрийте **SQL Editor** у панелі Supabase, вставте вміст файлу `supabase/migrations/202611160001_initial_schema.sql` і виконайте його один раз.
3. У **Project Settings → API** скопіюйте Project URL та publishable key (або legacy anon key).
4. Створіть локальний файл `.env.local` на основі `.env.example` і заповніть:
   `REACT_APP_SUPABASE_URL` та `REACT_APP_SUPABASE_ANON_KEY`.
5. Для GitHub Pages ті самі значення потрібно передати у середовище збірки через налаштування Secrets/Variables репозиторію. Після цього повторно зберіть і опублікуйте сайт.

**Важливо:** не додавайте до React-застосунку `service_role` або secret key. У браузері дозволено використовувати лише publishable/anon key; доступ обмежується політиками RLS.

Поки URL і публічний ключ не задані, сайт використовує локальний резервний каталог, а відгуки продовжують відкривати WhatsApp. Після налаштування ключів відгуки зберігаються в Supabase, каталог завантажується з таблиці `products`, а форма кошика створює записи в `orders`, `order_items` і `customers`.

### Telegram-сповіщення про нові замовлення

Сповіщення надсилає Supabase Edge Function після створення запису в `orders`. Токен бота зберігається лише в секретах Supabase і не додається до React-застосунку.

1. Створіть бота через [@BotFather](https://t.me/BotFather), відкрийте з ним чат і надішліть `/start`. Додайте бота до групи замовлень, якщо повідомлення мають надходити в групу.
2. Отримайте ID чату локально у PowerShell. Скрипт попросить токен прихованим вводом і виведе лише ID чатів із новими повідомленнями бота:

   ```powershell
   $secureToken = Read-Host "Токен Telegram-бота" -AsSecureString
   $pointer = [Runtime.InteropServices.Marshal]::SecureStringToBSTR($secureToken)
   try {
     $token = [Runtime.InteropServices.Marshal]::PtrToStringBSTR($pointer)
     $updates = Invoke-RestMethod -Uri "https://api.telegram.org/bot$token/getUpdates"
     $updates.result | ForEach-Object { $_.message.chat.id }
   } catch {
     Write-Error "Не вдалося отримати chat ID. Перевірте токен і надішліть /start боту."
   } finally {
     [Runtime.InteropServices.Marshal]::ZeroFreeBSTR($pointer)
     $token = $null
   }
   ```

   Для групи спершу додайте бота та надішліть у групу повідомлення; її ID зазвичай від’ємний.
3. У **Supabase → Edge Functions → Secrets** додайте `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` і `ORDER_WEBHOOK_SECRET`. Згенеруйте останній локально командою `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`; задайте те саме значення як секрет функції та заголовок webhook. Не зберігайте секрети у файлах проєкту.
4. Установіть Supabase CLI, увійдіть та прив’яжіть проєкт, потім опублікуйте функцію:

   ```bash
   supabase login
   supabase link --project-ref hmtqyvyvvcujwsdasvcf
   supabase functions deploy notify-order-telegram
   ```

5. У **Supabase → Database → Webhooks** створіть webhook для `public.orders`, подія `INSERT`, URL `https://hmtqyvyvvcujwsdasvcf.supabase.co/functions/v1/notify-order-telegram`. Додайте заголовок `x-order-webhook-secret` із тим самим значенням, що й `ORDER_WEBHOOK_SECRET`.
6. Не надсилайте токен бота в чат і не додавайте його до коду чи налаштувань React-застосунку.

Функція перевіряє секрет вебхука й отримує дані замовлення на сервері. Для цього потрібного доступу до таблиць вона використовує Supabase `service_role` із серверного середовища; цей ключ не потрібно додавати в код або секрети браузера.
